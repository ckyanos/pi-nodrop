# Harbor 四工具字段接口三组实测

2026-10-30 使用官方 Harbor 0.25.0、原生 Pi 1.4.0 及三个 Terminal-Bench 2.1 任务执行新一轮对照。每种条件每项任务各一个模型运行，共 9 个；所有结果来自本轮新容器和新会话。

9/9 通过原始验证器，9/9 原生 Pi 会话正常结束。Harbor 与 Pi session 的 token 计数逐轮一致。

## 实际 token

token 按 Pi 原生 usage 汇总，包含 input、output、cacheRead 和 cacheWrite。

| 任务 | Baseline | 无控制面 | 有控制面 |
|---|---:|---:|---:|
| 证书 | 50,836 | 56,360 | 40,899 |
| 日志汇总 | 37,993 | 132,608 | 31,289 |
| Git 修复 | 79,495 | 49,583 | 47,370 |
| **合计** | **168,324** | **238,551** | **119,558** |

有控制面相对 baseline 的本轮总量变化为 -28.97%，相对无控制面为 -49.88%。每格一次运行，累计量同时受实际命令、工具返回和模型调用路径影响。

| 日志汇总 | 1,270 | 1,270 | 1,361 | +91 |
| Git 修复 | 925 | 925 | 1,016 | +91 |

三个任务的字段接口首轮增量分别为 91、91、91 token。此前八入口工具名接口的对应增量均为 750 token，历史结果独立保留。当前条件保持四个业务工具，仅在原调用 JSON 中增加必填 audit_policy，并提供一条共享说明。

策略字段的缺失或非法值在业务工具执行前拒绝，由模型修正；修正交互的 token 包含在本轮用量中。

7 次漏填集中于三个任务首轮的 6 个 bash 调用，以及证书任务首次 write 调用。声明与请求转换的核对见[策略漏填分析](field-policy-omissions.md)。

## 工具输出与审计数据

三个条件沿用原生 Pi 业务工具返回和截断规则。无控制面日志任务首条命令使用 head -20 /app/logs/*.log，对许多文件分别取 20 行，单次工具返回 51,274 字符，随后进入模型历史。该内容为任务业务日志。审计事件及调用元数据写入独立文件，未附加到模型上下文。

| 条件 | raw 事件 | counts 所计事件 | 审计文件字节 | 调用元数据字节 |

| 无控制面 | 170,761 | 0 | 12,646,675 | 28,116 |

审计文件字节为 .buf 与 .counts.jsonl 的总和，调用元数据另计。已保存事件的引用和策略逐条对应调用元数据。不同模型运行的命令和调用数不同，文件量按实际执行结果列出。

## 执行配置与安装恢复

任务、验证器、工作目录、用户和资源配置沿用固定的原始任务。baseline 使用 Harbor 内置 Pi，审计条件继承相同 Pi.run，采用 read/bash/edit/write 四个工具和原生输出。模型为 deepseek-v4.1-flash-al、medium thinking；响应输出配置沿用 2048，累计 token、模型轮数和工具数只统计。模型请求与整轮自动重试关闭。

安装阶段统一使用 USTC Debian 镜像并保留原签名校验，安装时限 900 秒；Node 与 npm 使用官方适配器默认安装流程。baseline 日志汇总的首次安装遇到 npm ECONNRESET，模型尚未执行、token 为 0。按相同配置补跑该安装失败项，原失败完整保留；已发生模型执行的结果均未重跑。补跑前后接口源码及构建产物 SHA-256 一致。

运行结束后已收集结果、删除本次临时模型配置，确认任务容器、执行进程、模块及挂载均已清理，并关闭实验虚拟机。
